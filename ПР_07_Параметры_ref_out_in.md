## Теоретическая справка

### Сравнительная таблица

| Способ  | Что получает метод           | Может изменить значение вызывающей переменной? | Требование                       |
| ------- | ---------------------------- | ---------------------------------------------- | -------------------------------- |
| обычный | значение аргумента           | нет                                            | переменная должна иметь значение |
| `ref`   | ссылку на переменную         | да                                             | переменная инициализирована      |
| `out`   | ссылку для записи результата | да, и **обязан** записать                      | инициализация до вызова не нужна |
| `in`    | readonly-ссылку              | нет (запрещено компилятором)                   | используется только для чтения   |

### Передача по значению: что именно копируется

Для `int` копируется само число:

```csharp
int x = 5;
TryToDouble(x);
Console.WriteLine(x); // 5 — не изменилось

void TryToDouble(int number) {
    number = number * 2;
}
```

Для объекта класса «значение» — это ссылка на объект, и копируется именно она:

```csharp
class Hero {
    public string Name = "Игрок";
}

void ChangeName(Hero hero) {
    hero.Name = "Наруто Узумаки"; // изменит объект снаружи — ref не нужен
}

void ReplaceHero(Hero hero) {
    hero = new Hero();        // не заменит объект у вызывающего кода
}
```

**Вопрос:** почему `ChangeName` изменяет объект, видимый снаружи, а `ReplaceHero` не заменяет исходную переменную? Ответьте письменно в комментарии перед тем, как двигаться дальше.

### ref — передача по ссылке

```csharp
void DoubleValue(ref int number) {
    number = number * 2;
}

int x = 5;
DoubleValue(ref x);
Console.WriteLine(x); // 10 — изменилось
```

`ref` пишется **и** в объявлении метода, **и** при каждом вызове — чтобы в коде вызова сразу было видно: «эта переменная может измениться». Переменная, передаваемая через `ref`, обязана быть уже инициализирована до вызова.

### out — формализуем то, чем уже пользовались

Вы уже писали `int.TryParse(input, out int number)`. Разница с `ref`:

- `ref` не обязывает метод присваивать параметру значение и требует, чтобы переменная была инициализирована **до** вызова;
- `out` не требует инициализации до вызова, но метод **обязан** присвоить параметру значение на каждом пути выполнения.

Именно поэтому у `TryParse` используется `out`: методу не важно, что было в переменной раньше, — он сам обязан туда что-то записать.

```csharp
bool TryDivide(int a, int b, out int result) {
    // ?
}
```

### in — по ссылке, но только для чтения

`in` передаёт параметр по readonly-ссылке и запрещает менять его значение внутри метода. Для маленького `int` практический выигрыш незаметен — интерес представляют большие `struct`, для которых обычная передача по значению означала бы копирование всех полей:

```csharp
struct CharacterStats {
    public int Health;
    public int Damage;
    public int Armor;
}

void PrintStats(in CharacterStats stats) {
    Console.WriteLine($"HP: {stats.Health}");
    Console.WriteLine($"Урон: {stats.Damage}");
    Console.WriteLine($"Броня: {stats.Armor}");
}
```

**Вопрос:** почему следующий код не компилируется?

```csharp
void Print(in int value) {
    value = 10;
}
```

Объясните причину письменно.

### Необязательные параметры и именованные аргументы

```csharp
void PrintBox(int width, int height, int depth = 10, string color = "белый") {
    Console.WriteLine($"Коробка {width}x{height}x{depth}, цвет: {color}");
}
```

- Необязательные параметры (со значением по умолчанию) должны идти **после** всех обязательных в списке параметров.
- Именованные аргументы позволяют обращаться к параметру по имени при вызове — можно менять порядок и пропускать предшествующие необязательные значения.

## Итоговая задача. Проектирование системы персонажа

Это центральная часть работы. Объявления методов не даны — самостоятельно решите, какие параметры они должны принимать и какие из них будут `ref`, `out`, `in` или `необязательными`.

Разработайте несколько методов для работы с персонажем:

1. Метод получает отдельную переменную здоровья и должен изменить её у вызывающего кода.
2. Метод вычисляет итоговый урон и возвращает результат обычным `return`.
3. Метод пытается выполнить действие (например, применить умение) и возвращает одновременно признак успеха и дополнительный результат (например, величину эффекта).
4. Метод получает характеристики персонажа только для чтения (используйте `struct`, как в теории про `in`).
5. Метод имеет необязательный параметр настройки вывода (например, подробный/краткий режим).
6. Хотя бы один вызов использует именованный аргумент.

**Перед реализацией каждого метода кратко (1-2 строки в комментарии) укажите, почему выбран именно этот способ передачи параметра.**

В основной части программы продемонстрируйте вызов всех методов на одном-двух персонажах.
